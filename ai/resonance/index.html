Why I built it

I wanted to learn fine-tuning end to end: building a dataset, training on a free GPU, and above all evaluating whether the tuned model is actually better than the one I started from. A physics tutor was a good test because answers can be checked: the central equation is either there or not.

The first version, made for the Gemma 4 Good Hackathon in May 2026, trained, published an adapter and served a demo. Looking at it again months later, almost nothing worked as described, so I rebuilt it.

What was wrong with the first version

  • The prompts used Gemma 2/3 chat markers, which Gemma 4's tokenizer reads as plain text, so training, data and demo all used a format the model never knew.
  • The demo loaded the base model and never the adapter.
  • The "benchmark" ran only the base model, on 5 questions.
  • The training answers were written by the base model itself, so fine-tuning could only copy its own mistakes.
  • Over a third of the adapter's weights went to the vision and audio parts of the model, which text training never uses.

What I built

  • Data by distillation. Questions from a syllabus of about 120 topics and from recent arXiv abstracts; a larger teacher (Gemma 4 31B) writes the answers; an answer is kept only if it has both levels, valid LaTeX and no template leaks, after a second physics review by the teacher.
  • Training. QLoRA (rank 16) with Unsloth on one free T4, on the language model only, with the loss on the answers alone.
  • Evaluation. Base and tuned models answer 20 held-out questions; each answer is checked for format and for the key equation, and graded by an LLM judge with a reference answer. Models are compared question by question with a sign test.
  • Demo. A Gradio chat with three simulations (damped oscillator, wave packet, Kepler orbit) whose sliders update the plot in about 0.1 s, each tested against its closed-form solution.

The strong run had the lower validation loss and the worse physics: it wrote confident derivations that went wrong, such as Snell's law without refractive indices. The gentle run kept the base model's physics (6 wins each, 8 ties) while always using the two-level format and writing 22% fewer words. That one is published.

What I learned

  1. Lower loss is not better answers. The validation set was teacher text too, so a lower loss meant closer imitation of the teacher's style, not more correct physics. Only a held-out evaluation with a judge showed it.
  2. Imitation transfers style more than knowledge. Training a 2B model hard on a 31B model's derivations taught it what a derivation looks like, not how to do one, which matches Gudibande et al. (2023).
  3. Check the plumbing before the model. The chat template, which weights the adapter touches and whether the demo loads the adapter at all mattered more than any hyperparameter.
  4. Small evaluations need honest statistics. 20 questions detect only large differences; a sign test makes that explicit instead of hiding it.
