Why I built it

I was already using LLMs in projects, but much of what happened inside them was a black box to me. I wanted to understand each layer well enough to write it myself: the maths behind training, autograd, attention, tokenization, what the GPU actually does, and what turns a base model into a chat model. The rule was to write every piece myself, check it against a reference where one exists, and write down what I learned and what did not work.

What I built

  • Foundations. NumPy experiments for Understanding Deep Learning (Prince), chapters 2–9: shallow networks, losses as likelihoods, backpropagation with a gradient check, initialization, bias and variance, regularization. From Mathematical Introduction to Deep Learning (Jentzen, Kuckuck, von Wurstemberger): explicit ReLU interpolation against its error bound, and GD, SGD, momentum, Adagrad, RMSprop and Adam side by side.
  • micrograd and makemore. A scalar autograd engine tested against PyTorch, then character-level language models: bigram, MLP, BatchNorm and activation statistics, a full manual backward pass and a WaveNet-style model.
  • GPT and tokenization. A nanoGPT-style transformer on Tiny Shakespeare and a BPE tokenizer with GPT-4's split pattern and special tokens.
  • CUDA C++. Following NVIDIA's tutorials: Thrust, kernels, grid-stride loops, a shared-memory and warp-shuffle reduction, tiled matrix multiplication and streams.
  • A modern LLM. RMSNorm, rotary embeddings, SwiGLU and grouped-query attention, with a memory-mapped dataset, AdamW, warm-up and cosine schedule, gradient accumulation, checkpoints and top-p sampling.
  • Chat. Following nanochat: chat special tokens, a loss mask on the assistant's reply, a KV cache and supervised fine-tuning.
  • AI engineering and experiments. TF-IDF retrieval and RAG over the repository's own notes, a tool-calling agent with an AST-safe calculator, an eval harness, and a fixed-time-budget search loop inspired by autoresearch.

Results

  • The checks pass. 23 tests over autograd, tokenizers, the chat model and the agent loop. The KV cache generates exactly the same tokens as recomputing everything.
  • The small models learn. The micrograd MLP separates the two-moons data. The bigram model reaches an average loss of 2.45. The chat model goes from 0% to 97% on additions it never saw.
  • Initialization matters as the books say. With He initialization the activation variance stays stable through the layers. With smaller weights it vanishes, and with larger ones it explodes. With BatchNorm, saturated tanh units drop from 11–22% to about 2–3% per layer.
  • Scale is honest. My laptop has no NVIDIA GPU. The CUDA examples and the default GPT and LLM configurations are meant for one, so I ran only tiny configurations to check the code end to end.

What I learned

  1. Gradients accumulate. My first autograd assigned gradients instead of adding them, which broke any node used twice. Writing a gradient check before trusting a backward pass became a habit.
  2. A chat model is a data format. The architecture does not change: special tokens and a loss mask on the reply are what turn a base model into an assistant.
  3. Tokenization explains odd behaviour. Accented Portuguese letters are two bytes before any merge, and numbers split into arbitrary chunks. Both cost context and make arithmetic harder.
  4. Hardware shapes design. Memory-bound kernels, tiling and the KV cache explain why grouped-query attention, fused attention kernels and dimensions that are multiples of 64 exist.
